完整的模型链应该是：

```
  CLI 输入模型
      ↓
  Application / Service 输入模型
      ↓
  Domain Model
      ↙                     ↘
  Repository 持久化模型      Runtime 输入/输出模型
      ↘                     ↙
  Application / Service 结果模型
      ↓
  CLI 输出模型
```

用业务 PSM 类比就是：

```
  IDL Req
  → Service Params
  → BO / Entity
  ↔ DO / PO、下游 RPC Req/Resp
  → Service Result
  → IDL Resp
```

注意：Service 和 Repository 是代码层；Input、Result、Record 等才是这些层持有或传递的模型。

**一、完整的模型分类**

| 模型层                       | CLI 项目命名        | 业务 PSM 类比   | 职责                           |
| ---------------------------- | ------------------- | --------------- | ------------------------------ |
| 外部输入                     | XxxArgs             | IDL Request     | 原样接收用户参数               |
| 应用输入                     | XxxInput            | Service Params  | 去掉 CLI 细节后的标准化输入    |
| 领域模型**(domain)**         | Environment         | BO / Entity     | 表示稳定业务对象               |
| 持久化模型<br />(repository) | EnvironmentRecord   | DO / PO         | 描述磁盘 JSON 的格式           |
| Runtime 输入                 | ActivationVariables | Caller Request  | 调用 shell/操作系统组件的参数  |
| Runtime 输出                 | ActivationResult    | Caller Response | shell/系统组件执行或计算的结果 |
| 应用结果                     | XxxResult           | Service Result  | 表示一次业务用例的完整结果     |
| CLI 输出                     | XxxOutput / XxxView | IDL Response    | 面向用户展示的数据             |

后缀语义可以这样记：

- Args      外部 CLI 参数
- Input     Service 接收的应用输入
- Entity    业务中的稳定对象
- Record    存储格式
- Result    Service 的执行结果
- Output    CLI 最终展示结构

## 六、存储层设计
暂定使用 JSON 持久化，Skill 统一登记，Environment 通过 `skillId` 引用 Skill。

### 6.1 Skill 注册表

`$HOME/.hev/skills.json`

```json
{
  "schemaVersion": 1,
  "skills": [
    {
      "id": "skill_01",
      "identity": {
        "skillName": "common-env-init",
        "creator": "hev",
        "version": "1.0.0"
      },
      "realPaths": [
        "/absolute/path/to/common-env-init"
      ]
    }
  ]
}
```

### 6.2 Environment 注册表

`$HOME/.hev/environments.json`

```json
{
  "schemaVersion": 1,
  "environments": [
    {
      "id": "env_01",
      "name": "base",
      "revision": 1,
      "path": "$HOME/.hev/environments/env_01",
      "skills": [
        {
          "skillId": "skill_01",
          "mode": {
            "type": "auto"
          }
        }
      ]
    }
  ]
}
```

`mode.type` 取值为 `auto`、`always`、`interval` 或 `off`；当值为 `interval` 时额外保存 `everyTurns`。

## 七、CLI 与 Plugin 契约

Plugin 通过子进程调用 `hev` CLI。CLI 负责 Environment 和 Skill 的持久化与解析；Plugin 负责将解析结果绑定到 Harness Session，CLI 不保存“当前激活环境”。

### 7.1 调用规则

- Plugin 调用 CLI 时固定传入 `--output json`。
- `stdout` 只输出一个 JSON 对象，`stderr` 只输出日志和诊断信息。
- 成功时退出码为 `0`，失败时为非 `0`；失败时 `stdout` 仍返回结构化错误。
- Plugin 必须先校验 `schemaVersion` 和 JSON 结构，再使用返回数据。

### 7.2 公共返回结构

成功：

```json
{
  "schemaVersion": 1,
  "ok": true,
  "data": {}
}
```

失败：

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "ENV_NOT_FOUND",
    "message": "environment not found: coding"
  }
}
```

`error.code` 是给 Plugin 判断的稳定错误码，`message` 用于向用户展示。MVP 错误码包括：`INVALID_ARGUMENT`、`ENV_NOT_FOUND`、`ENV_ALREADY_EXISTS`、`SKILL_NOT_FOUND`、`SKILL_ALREADY_EXISTS`、`SKILL_PATH_INVALID`、`STORAGE_CONFLICT` 和 `INTERNAL_ERROR`。

### 7.3 CLI 命令契约

#### 创建 Environment

```bash
hev env create <env-name> --output json
```

```json
{
  "schemaVersion": 1,
  "ok": true,
  "data": {
    "environment": {
      "id": "env_01",
      "name": "coding",
      "revision": 1,
      "path": "$HOME/.hev/environments/env_01"
    }
  }
}
```

#### 注册 Skill 并加入 Environment

```bash
hev skill add <skill-id-or-path> --env <env-name> [--env <env-name>...] [--mode <mode>] [--every-turns <n>] --output json
```

```json
{
  "schemaVersion": 1,
  "ok": true,
  "data": {
    "skill": {
      "id": "skill_01",
      "identity": {
        "skillName": "code-review",
        "creator": "user",
        "version": "1.0.0"
      },
      "realPaths": [
        "/absolute/path/to/code-review"
      ]
    },
    "environments": [
      {
        "id": "env_01",
        "name": "coding",
        "revision": 2
      }
    ]
  }
}
```

传入路径时，CLI 先注册 Skill，已注册的同一物理路径直接复用原 `skillId`；传入 `skillId` 时直接建立 Environment 关联。`--mode interval` 时必须传入大于 `0` 的 `--every-turns`；其他 mode 不接受该参数。

#### 激活 Environment 组

```bash
hev env activate <env-id-or-name> [env-id-or-name...] --output json
```

```json
{
  "schemaVersion": 1,
  "ok": true,
  "data": {
    "environments": [
      {
        "id": "env_01",
        "name": "coding",
        "revision": 2,
        "skills": [
          {
            "id": "skill_01",
            "identity": {
              "skillName": "code-review",
              "creator": "user",
              "version": "1.0.0"
            },
            "realPath": "/absolute/path/to/code-review",
            "mode": {
              "type": "auto"
            }
          }
        ]
      }
    ]
  }
}
```

CLI 按入参顺序返回 Environment 组，并校验其 Skill 引用和物理路径。任一 Environment 不可用时整个命令失败，不返回部分结果。

#### 取消激活

```bash
hev env deactivate --output json
```

```json
{
  "schemaVersion": 1,
  "ok": true,
  "data": {
    "environments": [
      {
        "id": "env_base",
        "name": "base",
        "revision": 1,
        "skills": [
          {
            "id": "skill_00",
            "identity": {
              "skillName": "common-env-init",
              "creator": "hev",
              "version": "1.0.0"
            },
            "realPath": "/absolute/path/to/common-env-init",
            "mode": {
              "type": "auto"
            }
          }
        ]
      }
    ]
  }
}
```

`deactivate` 的固定语义是取消当前 Environment 组并返回 `base` 的完整装载结果；即使当前已经是 `base`，也返回成功。

### 7.4 Plugin 激活契约

```text
/hev env activate <env-name> [env-name...]
    ↓
hev env activate <env-name> [env-name...] --output json
    ↓
校验返回契约
    ↓
为当前 Session / Agent 更新 Skill Provider
    ↓
持久化 SessionBinding
```

Plugin 至少持久化：

```json
{
  "environments": [
    {
      "environmentId": "env_01",
      "environmentRevision": 2
    }
  ]
}
```

`/hev env deactivate` 调用 `hev env deactivate --output json`，然后用相同流程将 Session 绑定替换为 `base`。Session 恢复时，Plugin 使用已保存的 `environmentId` 列表重新执行 `activate`，在首次 Agent 调用前完成 Skill Provider 装载。激活操作必须串行化；CLI 调用或持久化失败时回滚到原 Provider 和原绑定。

### 7.5 兼容性规则

- 新增可选字段不升级 `schemaVersion`，Plugin 忽略未识别的可选字段。
- 删除字段、改变字段类型或改变现有语义时，必须升级 `schemaVersion`。
- Plugin 遇到不支持的 `schemaVersion` 时必须明确报错，不得猜测或降级解析。
