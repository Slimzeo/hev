去掉 Installer 后：Rattler 的运行时环境隔离模型

用户或外部工具负责创建可用 Prefix，并在其中自行执行 pip。Rattler 不维护包的 desired state，只负责把指定 Prefix 转换为当前 Shell 或子进程的运行上下文。

最小模型 existing prefix: &Path → Activator → activated env → child process。隔离来自不同 Prefix 中的 Python runtime 与 site-packages。

为什么传统工具复杂

它们同时承诺求解、二进制平台兼容、原子升级、回滚、可复现和非 Python 库管理。复杂度来自包生命周期，不来自 Prefix 隔离。

官方源可靠仍不等于简单

源只保证内容可获取；它不替客户端决定兼容组合、目标平台、升级边界和失败恢复。你的模型把这些职责明确交给 pip。

冲突归属

跨 Prefix 的版本天然分离；同一 Prefix 内依赖冲突归 pip。Rattler 侧只需正确切换 PATH、CONDA_PREFIX 与激活栈。

可选观测的限制

PrefixData 只扫描 conda-meta/*.json，不能完整反映 pip distributions。且 Activator 使用 Conda 的 CONDA_PREFIX；标准 venv 的 VIRTUAL_ENV 需另行适配。
