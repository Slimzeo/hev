00 · Research argument

这篇论文究竟要解决什么，方法又凭什么可信？

精确问题：在同一长寿命进程里，组件反复加载、卸载、替换和重配时，系统怎样既只撤销离场组件自己的副作用，又在 provider 出现、消失或换身份时，让依赖它的组件按正确顺序重解析和迁移生命周期？论文把前者称为时间可组合性，把后者称为空间可组合性。PDF p.4–6

Why

为什么写

进程重启粒度过粗；手写 cleanup 与初始化期 DI 不能共同处理组件级恢复和动态依赖。PDF p.4–8。

Problem

研究问题

能否在任意合法交错中，只撤销目标组件，同时保证 provider / consumer 的生命周期顺序？

Method A

revertible effect

每次 context 变更同时返回 inverse；runtime 逆序组合，形成组件自己的 accumulator。PDF p.9–17。

Method B

reactive coeffect

组件声明依赖；context 变化被分类为 activating、deactivating 或 neutral。PDF p.17–27。

Method C

fiber calculus

统一 context，加上四态 lifecycle 与十条规则，把局部机制提升到交错系统。PDF p.28–53。

Evidence

依据是什么

形式定理证明模型内性质；Cordis 给出可执行映射；Koishi 给出存在性与采用度案例。

Boundary

可信到哪里

不自动验证 inverse，不覆盖隐藏状态和外部 emission；无 benchmark，Agent Harness 仍是未来验证。

为什么可信，不是因为“有一个成功 Demo”

Table 1 穷举 lifecycle rule 的写集合，Theorem 59/61/63/64/66/73 在显式前提下覆盖任意合法 interleaving；Table 2 与 Algorithm 1–10 说明形式对象能落到 Cordis；Koishi 的 4000+ plugins 只补充可实现性与采用度。可靠性因此是“模型内有证明、实现有对应、现实中有案例”，不是“性能已被证明更好”。PDF p.39–67。
