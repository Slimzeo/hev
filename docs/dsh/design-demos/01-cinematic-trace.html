SCENE 02 / TWO ORTHOGONAL AXES

The research delta

同一条运行轨迹，必须同时回答两个问题。

时间维问「怎样只撤销我做过的事」；空间维问「当依赖身份变化时，谁该激活、停用或保持」。论文把两者统一进 context paradigm。

T

Temporal composability

Atomic effect 返回结果与 inverse。多个 inverse 组合成 fiber-local accumulator，并以 LIFO 顺序执行。正确性依赖 inverse witness 与跨 fiber 的 independence，而不是 runtime 自动证明。

effect α→effect β→inv β→inv α
S

Spatial composability

Coeffect specification 描述需求，resolution 给出 provider identity。context change 按满足性变化分类；consumer 因而能对 provider 的出现、替换与撤出做局部响应。

SCENE 03 / RESEARCH ARGUMENT

Why this paper exists

一条完整论证，
不是一个热插拔效果。

论文研究的是：组件交错增删时，怎样同时保住“只撤销自己”和“依赖有序迁移”。进程重启、手写 dispose 与初始化期 DI 各自只覆盖一部分。

01 / Research question

研究问题

同一长寿命进程里，目标 fiber 离场时能否只撤销自己的 context contribution；provider 变化时，consumer 能否重解析并先完成 teardown？

为什么可信，可信到哪里

SCENE 04 / PAPER EVIDENCE

Read the frame

四态不是 UI 状态，而是并发装配中的控制边界。

Reloading 与 Unloading 把「构造中的 target」和「仍对外可见的 committed」分开。这样 dependent 可以在 provider 切换期间沿有序规则退出，而不是读到半安装状态。

红色 transition：卸载、失败或回退相关路径
蓝色 transition：加载、提交与重新解析
规则由 calculus 的 lifecycle steps 约束
SCENE 05 / THEOREM EVIDENCE

Formal evidence

“只撤销自己”不是一句直觉，而是一条带条件的结论。

把成立条件与结论并置，避免把形式保证误读成任意 side effect 都能回滚。

THEOREM 61
RECOVERY EXACTNESS
在 pairwise independence 与 witness 等条件下，一个 fiber 的 accumulator 能从交错执行后的 context 中，精确撤销该 fiber 的贡献。

成立条件

Atomic inverse 在实际状态上满足 witness；相关 effect / iterator 两两独立；读写被限制在允许的 context 操作内。

结论支持

即使不同 fiber 的动作交错，目标 fiber 的 accumulator 仍可选择性恢复；Corollary 62 进一步给出 terminal recovery。

不证明什么

不证明业务逻辑正确，也不覆盖不可逆外部 emission；注册子 fiber 参与执行、隐藏共享状态或 independence 破坏时，不能直接套用。

SCENE 06 / THEORY TO CORDIS

Implementation bridge

形式模型最终落回 runtime 对象与方法。

论文 p.54–61 将理论实体映射到 Cordis core。这里展示的是概念 locator，不把伪代码冒充性能证据。

coeffect resolution→ctx.set() / ctx.get() / ctx.use()：提供、解析与响应依赖
target / committed→fiber.target / fiber.committed：区分构造中与对外可见实例
accumulator→fiber.dispose：按逆序组合本 fiber 的清理动作

Spatiotemporal composability
不是“插件能热插拔”的新说法。

它要求 runtime 同时保留可恢复的时间轨迹与可响应的空间依赖，并让 lifecycle、ordering 与 failure 都进入可核验的规则。Koishi 的 4000+ 插件生态是存在性与采纳度证据；论文没有提供 controlled benchmark，也不把 Agent harness 描述成已完成验证。
