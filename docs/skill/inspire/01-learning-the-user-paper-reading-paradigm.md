# 我从你的 DeepSeek Harness 论文解读范式里学到的东西

这次最强烈的感受是：**你要的从来不是“把论文讲懂”，而是把论文加工成一套可以被审计、被重组、被用于决策的知识基础设施。**旧版 SkillLens 解读之所以垃圾，不是因为它漏了几个数字，也不只是页面不好看；它从一开始就把任务误判成“总结一篇论文”，所以后面无论加多少卡片、图表和结论，都只能得到一张漂亮的摘要墙。

## 1. 你的范式不是文章范式，而是编译范式

我以前容易把论文解读看成一条直线：读论文 → 提炼重点 → 写文章。DeepSeek Harness 的真实结构是：

```text
原始 PDF
  → 版本与事实防漂移
  → 全文顺序取证
  → Claim–Evidence 法务账本
  → 唯一研究主线
  → 面向不同读者重新编译
  → 离线、交互、可验证的发布物
```

这里最关键的变化是：发布文章不再承担“完整性”。完整性由顺序笔记和证据账本承担；文章只承担一个读者任务。这让工程 Walkthrough 可以大胆按运行链重排，让研究稿按证据强度组织，让架构稿开篇就否决，而不用三篇都机械复述背景、方法、实验、结论。

## 2. “为什么可信”必须是一个独立章节

普通解读把实验结果当作可信度本身：作者跑了 benchmark，数字涨了，所以方法有效。你的范式要求继续追问：

- 这是定义、受控实验、统计检验、定性案例，还是工程推断？
- 对照组是什么？变量真的被隔离了吗？
- 数字支持哪条 claim？它不能支持什么？
- 证据是在同一 protocol 下可比，还是被不同任务/预算/模型混在一起？
- 结论在什么条件下会失效？

这意味着“limitations”不能只在文末礼貌列三条。每个强结论旁边都应有一条局部边界。DeepSeek Harness 给我的最大提醒，是把证据边界从免责声明提升成正文结构。

## 3. 图不是装饰，而是认知装置

旧版 SkillLens 页面虽然用了论文图，但多数只是“把图放进卡片”。你的范式里，论文原图是一份证据；解读者重绘是一种解释；交互实验是一台认知装置。三者不能混：

- 原图回答“作者到底报告了什么”；
- 重绘回答“机制怎样串起来”；
- 交互回答“当一个关键变量改变时，结论为什么改变”。

所以一个按钮如果只切换颜色或换一段文案，它不算研究交互。真正有效的交互会同步改变状态、条件、证据和结论。例如在 SkillLens 里改变 experience success ratio，不应只动一条曲线，还要同时告诉读者：为什么 SpreadsheetBench 和 ALFWorld 的最优配比不同，以及 all-failure 为什么仍然最差。

## 4. 三篇文章必须有三种思考顺序

我学到的不是“三种语气”，而是三种不同的认知路径：

- 工程稿按**运行因果**：输入怎样流过系统，在哪一步产生行为变化，失败怎样暴露。
- 研究稿按**证据依赖**：研究 delta 是什么，变量如何隔离，实验能支持多强的结论。
- 决策稿按**否决路径**：哪些条件没满足就不该采用，怎样试点，什么时候必须停。

如果三篇拥有同样的章节，只是标题和配色不同，就说明我没有真正理解读者任务。

## 5. 你重视的是“可撤销的判断”

DeepSeek Harness 的架构决策稿不是在替论文站台。它把每条建议写成 Gate、Pass、Stop、风险与 ADR，让读者可以合理得出“不用”。这背后是一种我很认同的工程价值观：**好的研究解读不是把读者推向一个结论，而是给出足够清楚的证据结构，让结论可以被拒绝、被缩小范围、被新的数据推翻。**

迁移到 SkillLens，这意味着不能因为论文平均 positive 就建议自动抽取并全量启用 skill。没有 held-out baseline、target-specific compatibility matrix、negative-transfer rollback 和真实 trace，最负责任的结论就是不发布。

## 6. 对我之后工作的约束

以后做你要的论文解读，我会先问自己六个问题：

1. 我是否读完了确定版本，物理页、正文、附录和图表覆盖是否可审计？
2. 我能否用一句话说清 research delta，而不是复述 contribution list？
3. 每条强 claim 是否有 locator、证据类型、支持范围和禁止外推？
4. 发布文章是否各自只有一个读者任务？
5. 图与交互是否真的改变理解，而不是装饰信息？
6. 工程建议是否带 baseline、Gate、stop condition 与回滚？

其中任何一项答不上，我都不应该急着做最终页面。

## 7. 这次旧版为什么失败

旧版 SkillLens 的失败可以非常具体地归因：

- 没有先核验本地 PDF 的物理页覆盖，甚至沿用了错误的粗略页数。
- 把目录名 `skillOpt` 与真实论文 SkillLens 混在同一语境，没有主动钉身份边界。
- 没有独立 product facts、research spine、evidence ledger 与 ordered notes。
- 主要结论来自摘要和少量表图，附录里的 prompt protocol、统计检验、behavior analysis、alternative harness、rubric discovery 与 contrastive cases 没有进入主叙事。
- 三个页面只是视觉方向，不是三种独立发布叙事。
- benchmark 数据源被列成资源清单，却没有被转成“怎么构建自己的 held-out skill benchmark”的决策合同。
- 说了“为什么有效”，但没有区分受控干预、相关性、定性机制与工程推断。

这不是润色能修好的问题，只能从研究底稿层重建。

## 8. 最后一句

我现在对你这套范式的理解是：**先把论文变成一个可审计的事实、主张和证据数据库，再为不同读者编译出不同的思考路径；视觉的职责是让证据关系可见，工程建议的职责是让判断可撤销。**

这次重做 SkillLens，我会用成品来证明我学到的是这套底层方法，而不是 DeepSeek Harness 的表面风格。
