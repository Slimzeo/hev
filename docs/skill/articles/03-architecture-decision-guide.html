No evidence, no rollout / 架构评审版

没有本地证据，
不要上线自动 Skill。

没有 held-out baseline、target-specific matrix、负迁移回滚、真实 trace 或预先冻结的预算，就立即否决。SkillLens 的核心警告不是“模型还不够会写”，而是同一份看起来合理的 skill 会因 extractor、target、domain 与 harness 的组合而涨分或伤害。

工程判断 自动生成、引入或持续演化 skill 都是一次可回滚的策略变更。它必须像代码与模型发布一样，有对照、分层矩阵、可观测性、预算和停止条件。

Immediate rejection / no-go

缺任何一项，
评审到此结束。

  • 同一 held-out split 上的 no-skill baseline
  • 按 target × extractor × domain 分格的结果
  • 可在一次发布窗口内执行的负迁移回滚
  • 带 task、skill、model、harness、cost 的真实 trace
  • 上线前写死的质量、延迟、调用与人工预算
论文用同一 held-out split 定义 utility，并保留单元级 Δ；它没有给生产 rollout、成本或回滚 SLA。定义见 PDF p.5；证据边界见 PDF p.11。

Executive decision

先否决默认上线，
再证明值得试点。

论文事实 SkillLens 不是用文本质量给 skill 打分，而是在同一 domain、同一 held-out test split 上比较 no-skill 与 with-skill，定义单元效应 Δ(E,M,D)。负值就是负迁移。p.5, Eq.3

BASE

基线能重跑吗？

不能稳定重跑 no-skill，就无法把 skill 的效果从模型、数据与 harness 漂移中分离。

CELL

看单元还是平均？

EE / TE 只用于角色摘要；上线对象必须回到具体 target × extractor × domain 单元。

TRACE

能解释策略变化吗？

至少要看到读取、选择、工具调用、失败机制命中与成本，而非只看终局分数。

BACK

能撤回哪一版？

必须同时 pin 住 model、skill、extractor、prompt、harness 与 benchmark 版本。

工程判断 “论文平均有效”“skill 写得很好”“更强模型生成的”都不是采用理由。论文主矩阵中 150 个单元有 37 个负迁移、1 个零变化；平均收益不能替代局部安全性。p.6–7, Table 1

决策对象要拆成三种，不要混成一个开关

生成（generate）：是否允许某个 extractor 从某类 experience pool 产出候选 skill？只决定候选如何来，不授予消费权限。

引入（adopt）：是否允许某个 target 在某个 domain / task cohort 消费某个固定 skill 版本？这是最小上线单元。

演化（evolve）：是否允许新 trace 触发再抽取、挑战 incumbent、替换或回退？这是带状态的持续治理系统，论文没有生产验证。证据缺口

Research contract

论文测的是闭环，
不是一份文档的观感。

研究问题 目标模型自己的原始成功与失败轨迹，经不同 extractor 压缩成 domain skill，再喂回同一 target 时，何时提升、何时伤害，utility 究竟由哪个生命周期阶段决定？p.2–5

Δ(E,M,D)

同一 held-out split 上，with-skill performance 减 no-skill performance；唯一直接决定某个部署单元是否更好的指标。p.5, Eq.3

EE(E,D)

固定 extractor，跨当前 targets 平均 Δ；描述 extraction efficacy，不是可移植能力证书。p.5, Eq.4

TE(M,D)

固定 target，跨当前 extractors 平均 Δ；描述 target evolvability，不保证新 skill 仍有效。p.5, Eq.5

为什么可信，以及证据边界

受控实验 论文固定 lifecycle 与 extraction scaffold，在五个 domain、六个 target、五个 extractor 上形成 150 个单元，baseline 与 skill 条件取三次独立运行平均；随后分别干预 experience composition、format、target transfer、judge rubric 与 meta-skill。p.4–10, Table 1, Figure 2–5

证据边界 主实验是“一个 domain-level skill 直接注入 system prompt”的受控设置；没有覆盖大型 library 的 retrieval、composition、conflict、长期漂移、线上成本、安全审批或回滚 SLA。p.15, Appendix A

Interactive adoption gate

点选不是投票，
是把证据缺口暴露出来。

每一项都必须有可打开的 artifact。勾选只代表“证据已存在且由评审看过”，不是“团队打算以后补”。

Skill adoption readiness
0 / 6 evidence gates closed

NO-GO · 0/6：证据链尚未建立。保持 no-skill 或当前人工 skill，不进入流量。

工程判断 六项全绿也只允许 time-boxed canary，不自动授予持续演化权限。持续演化还需独立的 challenger、漂移与 cooldown Gate。

Alternative matrix

自动抽取不是默认答案，
它只是六条路径之一。

先问变化来自哪里：稳定规则、一次任务上下文、可检索事实、反复出现的操作性失败，还是模型能力本身。不同问题对应不同载体。

方案最适合证据 / 维护成本主要失败模式推荐决策
Hand-authored skill规则稳定、风险高、专家知道明确 procedure / blacklist人工编写与 review 高；归属和变更原因清楚滞后、覆盖盲区、作者偏见高风险域默认 incumbent
Raw prompt / policy短、通用、几乎不变的行为约束最低；适合少量全局原则上下文膨胀、不可按 task 选择、版本耦合先用它验证是否需要 skill 系统
Retrieval memory事实、案例、近期状态与用户偏好需要按 query 召回索引、freshness、ACL 与引用验证召回错、陈旧、事实与 procedure 混淆信息问题优先，不把记忆伪装成流程
Auto-extracted domain skill重复错误可从真实 trace 提炼，且能在 held-out task 重跑最高：experience、extractor、matrix、rollout 全链治理负迁移、抽象过度、target mismatch、drift只做 target-scoped challenger
Tool / deterministic workflow步骤可验证、动作高风险、结果要求确定实现成本高；运行证据最强覆盖有限、接口维护能编码成约束时优先于自然语言 skill
Fine-tune / policy update高频稳定行为需要降低 prompt 成本或形成模型内能力数据、训练、评测与回退成本极高能力干扰、不可见漂移、回滚慢skill 证据稳定后再评估

Generate & adopt

生成候选可以自动，
获得流量不能自动。

SkillLens 最有用的工程启示是把 experience pool、extractor 与 target compatibility 当成三份独立合同。

Contract A / experience

轨迹必须有来源与结果

记录 task、target、model build、harness、outcome、error taxonomy、时间与数据权限。成功说明可复用策略，失败暴露真实机制；不要只采“漂亮成功”。论文的 success/failure mix 结果见 p.8, Figure 2。

Contract B / extraction

Extractor 只生成 challenger

相同 pool 可由多个 extractor 竞争。更强 executor 不必是更强 extractor；SpreadsheetBench 中 Gemini-3.1-FL 的 EE 为 +5.86 pp，GPT-5.4 为 +1.67 pp。PDF p.6, Table 1。

Contract C / consumption

Skill 与 target 成对发布

同一 skill 对不同 target 的 utility 可显著变化；strong-pool skill 的收益在目标间从 +1.8 到 +9.5 pp，weak-pool skill 对 GPT-5.4 为 −2.0 pp。p.9–10, Figure 4

候选 skill 的内容 Gate

WHY

Failure mechanism

指出 agent 为什么失败，而不是仅写“要谨慎”“先理解需求”。

HOW

Actionable specificity

使用 domain object、tool 与 step-level remedy，让 target 能直接执行。

BAN

High-risk blacklist

明确禁止会稳定造成伤害的动作模式，并给安全替代。

RUN

Downstream proof

前三项只决定值得进入 benchmark；最终仍由 target 的 held-out Δ 决胜。

论文事实 三个维度来自 utility-grounded 对照筛选；better-rate 分别为 65.5%、66.0% 与 64.6%。这些数字只描述论文 pair 集合上的对齐，不是上线阈值。p.10–11, p.23, Table 13

Continuous evolution gate

持续演化的核心，
不是“持续生成”。

它是一个 incumbent–challenger 系统：只有新证据足以否定旧版本时才替换；没有新证据时保持静止。

Observe

收集可审计 trace

按失败簇、target、domain 与版本分桶；隐私与权限先于 extraction。

Propose

生成 immutable candidate

记录 pool manifest、extractor、prompt 与父版本；禁止原地覆盖。

Challenge

跑冻结矩阵

同时对 no-skill 与 incumbent；先看负 cell，再看平均收益。

Canary

小流量双轨观测

真实 trace 验证 benchmark–production gap；预算触发自动降级。

Promote

显式晋升或淘汰

只移动版本指针；保留 lineage、证据包、旧 artifact 与回滚演练。

Meta-skill 也必须被当作候选干预

受控实验 论文把 utility 筛选后的三维 rubric 写回 extraction prompt，在 ALFWorld、SpreadsheetBench、SWE-bench × 三个 target 的九个单元中全部优于 original，平均 +1.55 pp；未经 utility 筛选的七维 plausibility guidance 平均 −0.59 pp。p.10–11, p.22, Figure 5, Table 11

工程判断 禁止“候选生成后自动覆盖 production skill”。Meta-skill 的任何变化都可能同时改变所有后续候选，是高爆炸半径的控制面发布：必须版本化、跑固定 golden set、跑 target matrix、canary，并保留一键 pin 回旧 extractor policy。
Rollout & rollback

负迁移不是异常分支，
而是主流程的一部分。

论文在受控矩阵中直接观察到负 Δ；生产系统应把“候选伤害某个 target”设计成可检测、可隔离、可撤回的常态。

最小 trace schema

WHO

Identity

target build、extractor build、skill ID / version、prompt policy、harness image。

WHY

Selection

task / cohort、是否命中、选择原因、候选集合、fallback 原因。

WHAT

Behavior

关键观察、tool calls、失败机制、blacklist 命中、最终 outcome。

COST

Budget

latency、tokens、model / tool calls、人工 review、重试与错误。

工程判断 回滚应是“切换 immutable version pointer + 清除选择缓存 + 继续记录 affected cohort”，而不是现场重写 skill。若 no-skill baseline 比 incumbent 更安全，no-skill 必须是一级 fallback，而不是被系统当成故障。
Risk board & stop conditions

最大的风险，
是把代理指标当真实效用。

漂亮文本、强 extractor、历史平均收益与单次 canary 都可能制造虚假安全感；治理要围绕可反驳的 downstream 证据。

R1 · Critical

目标模型负迁移

证据：主矩阵有 37 个负迁移单元，ALFWorld 有 14/30 个负值。p.6–7, Table 1
控制：target-scoped artifact、cell gate、no-skill fallback。

R2 · Critical

Benchmark 泄漏或基线漂移

风险：experience 与 held-out task 重合，或 model / harness 更新使 Δ 失去可比性。
控制：split hash、近重复审计、run manifest、版本重测。

R3 · High

文本 Judge 反向选择

证据：unguided judge 在 151 个 high-gap pairs 上准确率 46.4%，当差距至少 5 pp 时仅 15.8%。p.9, p.20, Figure 3
控制：judge 只做 triage，最终看 execution。

R4 · High

Experience pool 中毒

风险：失败标签错、攻击 trace、异常事件被过度抽象为普遍规则。
控制：provenance、异常隔离、人工复核高风险 blacklist、组成消融。

R5 · High

Meta-skill 放大错误

证据：未经 utility 筛选的 plausibility guidance 平均 −0.59 pp。p.10–11, p.22, Table 11
控制：控制面版本化、固定 golden set、停止自动生成。

R6 · High

Harness coupling

证据：替代 harness 子集仍有正负交互，平均 +0.4 pp，最差单元 −5.5 pp。p.20–21, Table 10
控制：接近生产的 second harness 与 shadow trace。

R7 · Medium

策略僵化与过度执行

证据：skill 会改变 exploration 与 tool-use；更结构化的 workflow 对弱 target 可能增加执行错误。p.10, p.18–19
控制：策略切换条件、scope、拒绝不适配任务。

R8 · Unknown

生产 ROI 不成立

缺口：论文 Appendix A/B 说明受控范围与算力/API 设置，但不报告线上 P50 / P99、token / call cost、人工维护、安全审核或 rollback SLA。p.15–18 · Appendix A/B
控制：本地预算与真实流量 canary。

任何一条命中，就停止晋升或冻结演化

工程判断 任一计划上线的 target / cohort 低于 no-skill 或 incumbent 的质量 floor，哪怕总体平均仍为正。

工程判断 不能复现 baseline，发现 train / held-out 污染，或 model、prompt、tool image 版本无法追溯。

工程判断 真实 trace 出现新严重错误、危险动作或策略僵化，而离线 benchmark 没有对应 case。

工程判断 P99、token / call、人工 review 或存储超过 ADR 预注册预算；不得事后抬高阈值。

工程判断 不能在一个发布窗口内 pin 回 incumbent / no-skill，或清除选择与 retrieval cache。

工程判断 数据 provenance、隐私、许可或删除链路不完整；停止新的 experience ingestion 与 extraction。

工程判断 没有 owner 审批新版本、处理报警与复盘负迁移；系统自动转为 Frozen。

最终建议

工程判断 默认选择“不要自动上线”。只有当真实重复失败值得固化、held-out baseline 可复现、每个待上线 target 的 matrix 通过、trace 能解释行为、预算预先冻结、回滚已演练时，才把 auto-extracted skill 作为 target-scoped challenger 进入 canary。持续演化另开 ADR，默认 Frozen。
